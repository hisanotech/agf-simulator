### 時間基準の消費モデル

- `battery.consumptionModel = active_time`、`activeReferenceMin = 360`、`activeReferenceConsumptionPct = 70` を新規UIシナリオの初期値とする。消費は `対象稼働ms / 21,600,000 × 70` ポイント。
- 対象は空走・荷受け、積載走行・荷下ろし、充電場所および待機場所への走行。停止旋回はRunの設定で対象に含め、初期値は有効。未割当待機、荷下ろし許可／設備空き待ち、包装機入口待ち、充電待ちは対象外。待機時の補機消費が実機でゼロと確定した意味ではない。
- 整数ミリ秒の稼働累計を初期／充電終了時の残量から差し引き、小数6桁で保持する。無関係なイベントの増減で消費量が変わらないよう、イベントごとの丸め差分を累積しない。
- 実行終了時点の未完了走行も経過分だけ消費する。充電中の残量も既存の充電速度から算出し、終了時刻のスナップショットを記録する。電池が途中で不足するシナリオはエラーとし、0%のまま搬送を続行しない。
- 合成グラフでは区間走行、停止旋回、荷受け／荷下ろし姿勢移行、フォーク挿入済み処理を別イベント・時間区分で計測する。旧固定時間Scenarioは明示的な旧モデルとして保持する。充電閾値は搬送完了時や待機場所到着時に再判定し、タスク途中の充電割込みや完遂可能エネルギーの事前予約は現場仕様として未確定。
- `consumptionModel = per_task` または項目省略の旧シナリオは、従来の `consumptionPct` を完了時に差し引く。旧1.5ポイントと時間消費を二重に適用しない。

## 5. AGF選定方式

候補は「待機中かつタスク実行可能」「バッテリー予約条件に適合」「設備・経路制約に反しない」車両に絞る。

- `area_first`（今回確定した通常選定方針）：**タスクの目的地エリア（荷下ろし先エリア）と現在エリアが一致する実行可能AGFを優先**し、その候補の中でバッテリー残量が少ない車両を優先する。同残量時のID順は既存ハーネスの暫定的な再現性ルールとし、正式な同率処理は未確定。**荷受け元エリア優先にはしない。**
- `low_battery_first`：エリア優先なしで低残量順、同率ならAGF ID順。
- どちらの方式でも、タスク実行中・充電中・充電待ち・異常・通信異常・有人モードは候補外。
- 目的地エリアに実行可能な候補が1台もいない場合の待機・他エリアからの選定／移動方針は未確定。勝手に低残量機を別エリアから確定割当しない。
- 開発ブランチの選定ハーネスは `task.destinationArea` を必須として目的地エリア優先を実装済み。目的地候補不在時は原則待機し、他エリアからの選定はシナリオで明示した仮定としてのみ許可する。
- 方式Bでも空走距離・走行時間の計算から現在位置を消さない。
- 比較時は生産入力列、設備、初期位置・残量、閾値などの外生条件を揃え、選定方式以外を変更しない。

**タスク種別の優先順位や割込み・予約方式は未確定**。01→02→03→04→05を固定の優先順位と断定しない。走行能力・充電余裕の予約判定は今後詳細設計する。

## 6. 搬送共通フロー

`REQUESTED → ASSIGNED → MOVING_EMPTY → WAIT_PICKUP_PERMISSION → PICKING → MOVING_LOADED → WAIT_DROPOFF_PERMISSION → DROPPING → COMPLETED → IDLE`。

1. 割当前に対象タスク・車両状態・設備可否を確認する。
2. AGF現在位置から最初の荷受け点へ移動する。
3. 荷受け位置到達・設備許可後に荷受けし、`carriedPalletId`を設定する。
4. 指定終点まで搬送し、受入許可後に荷下ろす。
5. 履歴・電池残量を更新し、タスクと積載を解除する。

区間時間は走行グラフとRunの設定値から算出する。区間別方向・車線・干渉制御は[AGF通行・車線仕様書](09-traffic.md)を正とする。PZは物理的には共有走行領域とし、交通制御上の北側設備レーンを東→西、南側外通路レーンを西→東の各1車線とする。必要な接続地点で明示されたレーン変更を行い、西端／東端だけを経由する不要な迂回を要求しない。倉庫の西2本・東2本は、各側で保管ブロック側を北→南、壁側を南→北とする。保管行は双方向1車線、防火SH通路群は双方向2車線を維持する。レーン、競合領域、停止位置を進入前に確認し、同一区画への重複進入やAGFの貫通を禁止する。隣接保管行へ2台が同時進入することは可能だが、近接減速の値・距離閾値は未確定。**合成描画座標や仮定速度から実CADの距離・確定ETAを主張しない。**

### 6.1 進行方向変更時の旋回制御

AGFは走行中に進行方向を変更するとき、向きを瞬時に切り替えない。次の進行方向へ向ける必要がある旋回ポジションへ到達したら一度停止し、車体の並進移動を止めた状態で旋回してから次区間を走行する。

1. 現在の進行方向と次区間の進行方向から、必要な旋回角度を求める。
2. 旋回ポジションへ到達した時点で並進速度を0とし、状態を `TURNING` にする。
3. 旋回時間は、Runで使用する旋回角速度と必要旋回角度から算出する。基本式は `turnDurationMs = abs(turnAngleDeg) / turnRateDegPerSec * 1000` とする。
4. 旋回時間中は同じ位置に停止したまま車体向きだけを更新し、旋回完了時に `headingDeg = turnTargetHeadingDeg` とする。
5. 旋回完了後にのみ、次走行区間への進入要求を行う。
6. 必要角度が0度なら旋回イベントを挟まない。
7. AGF干渉回避で退避方向へ向きを変える場合も、この旋回制御を共通で適用する。回避終了後に元の進行方向へ戻す必要がある場合も同様とする。

`turnRateDegPerSec` の暫定初期値は12.1deg/s。0.3m/s÷1.424mを角度へ換算した等価値であり、実測停止旋回速度ではない。Scenarioから変更可能にし、根拠区分を保存する。実機での停止旋回角速度、減速開始距離、停止までの減速時間、旋回後の加速時間は未確定であり、未確認の時間を勝手に加算しない。

### 6.2 AGF干渉回避時の共通原則

AGF同士の干渉回避では、回避するAGFの進行方向変更にも§6.1の旋回制御を適用する。干渉時の通行優先、追い越し、荷役姿勢による通過可否の詳細は[AGF通行・車線仕様書](09-traffic.md)を正とする。回避用の実停止点、退避経路、必要離隔、検知距離は未確定であり、実図未確認の位置を生成しない。

通常の競合は進入前停止を基本とする。既に区間内のAGFを優先し、未進入同士では積載車を優先して空荷車が譲る。同条件は要求／イベント順を用いる `synthetic runtime tie-break` として記録し、AGF番号順を現場の通行優先規則にしない。明示退避経路を持つ移動可能車が1台ならその車、両方なら空荷移動車を回避側の候補とする。架空の退避位置・経路は追加しない。

### 6.3 搬送01の包装機入口待ちと限定追い越し

荷受け後に包装機入口の在荷・有効予約・容量・受入許可を確認し、予約できない場合は荷受けしたPGW前で積載とタスクを保持する。包装機方向へ停止旋回した後に `WAITING_WRAPPER_INPUT` とし、別の仮待機場所へ移さない。設備前待機領域は合成モデルとして明示し、PZの両レーンを塞がず、車体を貫通して通過させない。

同方向追い越しは原則禁止。例外は搬送01の包装機入口待ちで完全停止し、発進予定のないAGFによって正規レーンが物理的に塞がれた場合に限る。明示された追い越し経路について、レーン変更開始部・反対レーン区間・待機車横の競合領域・正規レーンへの復帰領域を開始前に一括予約する。経路上の実レーン資源、排他停止点、復帰先も空きを確認し、全行程完了まで保持する。反対側の通常走行車や予約を優先し、空きがなければ追い越し側が待つ。逆方向の一時使用はこの予約経路だけに限定し、完了後は正規レーンへ復帰する。通常移動中、一般交通待ち、充電待ち等へ例外を広げない。

待機車は包装機入口予約、自車前方レーンと競合領域の空き、横の追い越し完了を確認してから発進する。包装機入口待ち時間を区間走行・荷役と重複せず記録し、Run終了時の未完了理由は「包装機入口待ち」と表示する。実CADの待機・追い越し位置、離隔、経路は未確定。

## 7. 充電共通フロー

1. バッテリー残量が40%以下になった時点で充電要求を作成する。
2. 実行中タスクがある場合の「中断か完了後か」は未確定。現在タスクを勝手に解放しない。
3. 充電場所へ移動して到着する。
4. 空きがある充電器1口を専有し、充電開始する。2口満杯の場合は充電待ち。
5. 1%=2.4分の設定で80%まで充電し、充電終了イベントを記録する。
6. 充電器を解放し、通常搬送の実行可否を再評価する。

充電器本体とAGF停車位置は別の地物として扱う。タスク実行不可・充電場所への未到着・満杯状態のまま充電開始しない。

## 9. 受入条件・未確定

- AGF1台1タスク、積載パレット1件、充電器1口1台を強制する。
- 使用不可の車両を選定対象に含めない。
- 同じ候補からは選定方式に従い再現可能なIDを返す。

## 10. 2026-09-29 初期配置の追加

初期状態では、**AGF1を充電場所1、AGF2を充電場所2、AGF3をHP1、AGF4をHP2** に配置する。この対応は初期配置専用であり、通常運転時の帰還先をAGFごとに固定するものではない。

充電場所に初期停止しているだけのAGFは通常タスクへ選定可能で、充電器本体を占有せず、充電時間を計上しない。実際に充電開始条件を満たし、既存充電フローへ入った時点でのみ`CHARGING`と充電器占有を成立させる。充電場所1/2と充電器1/2を固定対応させず、実充電開始時に空き充電器を使用する。

この規定は初期配置に限る。通常運転時の待機先は製品倉庫内の4か所（HP1・HP2・柱前東・柱前西）とする。AGFごとの専用待機場所は設けない。帰還時は `HP1 → HP2 → 柱前東 → 柱前西` の順に、未占有かつ未予約の最初の待機場所を選定し、選定時点で予約する。充電場所1・2は通常待機先にしない。パレタイズエリアに通常待機場所は設けない。

## 11. 2026-09-29 タスク完了・HP復帰の追加

利用者指示により、タスク完了後は充電判定、既存選定基準、次タスクへの直行または製品倉庫内待機場所への復帰を順に行う。復帰先はAGF固定ではなく、`HP1 → HP2 → 柱前東 → 柱前西` の優先順位で空き場所を決定する。**PZでタスクが終わり次タスクがない場合、PZ内に待機せず必ず製品倉庫側へ復帰を開始する。** 復帰中は新規割当不可。充電完了後も、次タスクがなければ充電場所に残らず製品倉庫内待機場所へ復帰する。待機場所への走行を走行・荷役時間による電池消費に含め、到着時も閾値を再判定する。待機・交通待ち・許可待ちは消費対象外。AGFごとの固定待機場所は設定しない。帰還先の選定は共通優先順位を用いる。
