# 01. 設備仕様書 v1.3

**独立仕様書**／関連：[全体](00-overview.md)・[01搬送](02-transport-01.md)・[02搬送](03-transport-02.md)・[03搬送](04-transport-03.md)・[AGF](07-agf.md)

## 1. 目的

設備単位で「在荷・容量・処理中・要求・許可・停止／異常・占有」を持ち、搬送要求発生から荷受け・投入・入庫までの状態遷移を一つのシミュレーション時刻で管理する。設備の機械制御そのものは実装対象外。

## 2.1 基準Runのニュートラル初期状態

基準シミュレーションは、明示した初期装填以外の仕掛かりを持ち込まないニュートラル状態から開始する。

- 搬送01～05の既存タスク・予約：なし
- パレタイザ製品バッファ：空
- 包装機の投入・回収・処理中パレット：なし
- 仮置き場：空
- 製品倉庫：初期製品在庫なし
- マガジン5台：各10枚
- 整列機5台：各10枚
- 設備異常・通行異常：シナリオで明示されない限りなし
- 充電中AGF：なし

AGFの初期位置、初期バッテリー100%、待機場所・充電場所の扱いはAGF仕様を維持する。特殊な充電競合・異常復旧・回帰テスト用シナリオは、明示的な検証シナリオとしてこの基準Runと区別する。

## 3. パレタイザ／搬出コンベア

**入力：** 生産・PLC搬出完了イベント、荷受け許可、異常状態。  
**状態：** 系列ID、在荷パレットIDのキュー、現在数0～2、搬出時刻、01要求・割当状態。  
**出力：** 01要求（PLC搬出完了を契機）、荷受け許可、荷受け実績、満杯・異常の保留理由。

各系列の実パレット搬出には空パレットを1枚使用する。各系列がどの空パレットマガジンから供給を受けるかは lineMagazineMap として明示設定し、未確認の対応関係を系列番号や設備並びから推測しない。対応マガジンの残数が1枚以上ある場合だけ1枚を消費して実パレット搬出を成立させ、PALLET_EXITED と01要求へ進む。対応マガジンが0枚の場合は実パレットを搬出せず、パレタイザを空パレット待ちとして保留する。

各系列の搬出頻度は**設定画面から分単位で個別変更可能**とする。初期値は設備能力100%を前提に算出した理論パレット排出タクトを用い、GWI 17.2、GWII 36.5、GWIII 36.5、GWIV 22.9、GWV 25.3、GWVI 21.5、GWVII 36.5、GWVIII 36.5 min/PL とする。これは理論値であり実PLC実績ではない。対応する理論物流量は順に3.5、1.6、1.6、2.6、2.4、2.8、1.6、1.6 PL/hr（表記丸め）で、全8系列同時の瞬間最大は約17.8PL/hr。24時間理論出来高は84、39、39、63、57、67、39、39PL、合計428PL/日で、実績最大約250PL/日とは区別する。容量2PLを越す実搬出を成立させない。AGFが荷受けした段階で該当パレットをバッファから除く。

## 4. 空パレットマガジン

**状態：** 残数、補充必要、03発行／補充中フラグ、投入許可、異常、投入実績。**初期残数は全5台10枚**。最大容量は未確定。

空パレット払い出しで残数が**ちょうど3枚になった遷移**を検知し、まず「補充必要」状態を1回成立させる。在荷10枚の利用可能な整列機がある場合だけ03タスクを発行する。全整列機が空なら03タスクは発行せず、補充必要状態を保持する。投入時は設備残数と許可を再確認し、投入完了イベントで+10PLする。残数マイナス、最大容量超過、要求重複はエラー。

## 5. 包装機

| サブリソース | 制約 |
| --- | --- |
| 投入バッファ | 1PL |
| 包装処理中 | 1PLの独占処理 |
| 回収バッファ | 2PL |
| ラベル・出口 | 完了／搬出OKを別状態で管理 |

**処理：** 01または04の投入完了 → RFID／製品情報照合 → 包装開始 → 包装完了 → ラベル貼付完了 → 出口到達 → 搬出OK → 02要求。包装タクトは3.3分/PL（能力18PL/hrという丸め表記との差に注意）。ラベル・コンベア移送・荷役の時間は未確定で、包装タクトだけで全工程を完了させない。

投入満杯なら01/04の荷下ろしを待機、回収満杯なら包装後の搬出を待機させ、在荷を消さない。同じパレットIDを工程で引き継ぐ。

## 6. 空パレット整列機

それぞれ専用荷受け点、在荷数、AGF荷受け許可、予約・占有状態を管理する。**初期状態は5台すべて10枚装填済み。03の10PL荷受け完了時点で対象整列機を0枚（空）にする。空の整列機は03供給元候補にしない。** 整列機は作業者の画面操作で手動補充し、個別補充は対象機を10枚へ、全機一斉補充は5台すべてを10枚へ戻す。すでに10枚ある機体へ加算して20枚にはしない。補充後は未処理のマガジン補充必要状態を再評価する。整列機とマガジンは固定1対1で結ばない。

## 7. 製品倉庫・仮置き場

- 倉庫は西・東というエリアだけでなく**個別ロケーションID**と在庫・容量を保持する。02/05の投入許可と在庫更新は個別位置で行う。
- 仮置き場は3か所。04/05が同じ在荷パレットを同時に予約しない。各位置に荷役停止点を持たせる。
- 空パレット保管エリアは整列機への有人供給元として区別し、AGFの03直接荷受け場所にはしない。

## 8. シャッター／通行設備

走行グラフの進入・退出方向と、各シャッターの停止位置・通行可能条件をシナリオで管理。基本的な通路は双方向でも、エリアへの出入りには個別ルールを適用する。通行許可がない区間は通過成立させず待機し、許可が成立したら通過イベントを記録する。各停止点と走行線の実座標は未確定。

## 9. 設備共通データとイベント

`equipmentId`, `type`, `state`, `capacity`, `occupiedPalletIds`, `permission`, `reservationTaskId`, `locationId`, `sourceStatus`。主要イベント：`PALLET_EXITED`, `MAGAZINE_USED`, `MAGAZINE_REFILL_REQUESTED`, `ALIGNER_READY`, `WRAP_STARTED`, `WRAP_COMPLETED`, `LABEL_COMPLETED`, `EXIT_READY`, `STORE_COMPLETED`, `SHUTTER_PASSABLE`。イベント名の追加はエンジン実装時に統一する。

## 10. 設備受入条件／未確定

- 系列2PL、包装投入1PL・回収2PL、充電器2口を超えない。
- 系列1～8の搬出頻度は設定画面から分単位で個別変更でき、各系列のRun入力条件に反映される。初期値は理論パレット排出タクト（17.2 / 36.5 / 36.5 / 22.9 / 25.3 / 21.5 / 36.5 / 36.5 min/PL）を使用する。
- 残数3枚の補充要求は未完了中に重複しない。投入実績前に+10しない。
- 空の整列機に03を発行・割当しない。整列機は在荷10枚のときだけ03供給元にでき、荷受け完了後は0枚になる。
- 整列機の個別補充・全機一斉補充は手動操作とし、補充後は10枚へ復帰する。
- 倉庫・仮置き場の在荷を重複搬送しない。
- **未確定：** 個別設備座標、倉庫個別容量、マガジン最大容量、区間別処理時間、各シャッター停止位置・走行線。マガジン初期残数10枚、整列機初期在荷10枚は確定。
