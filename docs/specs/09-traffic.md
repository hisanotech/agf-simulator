# 09. AGF通行・車線仕様書 v0.9（共有走行領域・一方通行・限定追い越し）

**独立仕様書**／関連：[全体マップ](08-map.md)・[設備](01-equipment.md)・[AGF](07-agf.md)・[経路指定ガイド](../route-annotation-guide.md)

> この文書は走行可否と車線の確認台帳。図面の矢印をそのまま「一方通行」「2車線」とは解釈しない。実図、実座標、現場識別情報、提供資料の名称はこの公開リポジトリに保存しない。

## 1. 確定の順序

1. **第1段階：通行できる場所を確定。** AGFが通過できる通路区間、設備への取付け通路、通行禁止区画、必要な通行許可を区間ごとに確定する。この段階では往来可能性、車線数、すれ違い可否、停止・旋回の安全性を確定しない。
2. **第2段階：第1段階で通行可能とされた区間ごとに、方向・車線数・すれ違いを確定。** 「双方向通行」と「2車線」を別属性とする。双方向1車線なら同時すれ違いの可否と退避／区間占有制御を別に確認する。
3. **第3段階：停止・旋回・干渉回避・優先順位・区間占有・距離・速度・時間を確認。** 方向変更時に「停止→旋回→再発進」とする制御、干渉時の回避側選定、同方向追い越し禁止、荷役姿勢による通過可否は利用者確認済み。実停止座標・退避経路・実測旋回角速度等の未確定値は推測で補完しない。利用者指定の暫定初期値は実測値と区別して入力条件へ保存する。

## 2. 判定単位と属性

**通路（Segment）**はシャッター、交差点、分岐、設備取付け口など、通行条件が変わる地点で分割する。設備・保管ロケーション自体と、そこへアクセスする走行通路を混同しない。

| 項目 | 値の例 | 確認段階 |
| --- | --- | --- |
| `segmentId` | 公開用の抽象ID | 初期 |
| `access` | `allowed` / `forbidden` / `unresolved` | 第1段階 |
| `accessScope` | 空走／積載／充電移動等、条件に差がある場合 | 第1段階 |
| `permission` | シャッター通行OKなど必要条件 | 第1段階 |
| `direction` | 双方向／指定方向のみ／未確定 | 第2段階 |
| `laneCount` | 1／2／その他／未確定 | 第2段階 |
| `simultaneousPassing` | 可／不可／制御条件付き／未確定 | 第2段階 |
| `turnStopStatus` | 確定／仮／未確定 | 第3段階 |
| `evidenceStatus` | 利用者確認／図示候補／未確定 | 全段階 |

通路方向、車線数、同時すれ違いは独立して記録する。矢印の本数は車線数を意味しない。製品パレットの保管マスは個別ロケーションであり、列間にAGFが進入する通路と区別する。利用者が「置き場ロケは通行可能」と補足したため、ロケーションへの進入・荷役は可能とするが、全マスを無条件に走行可能な道路としてグラフ化しない。

### 5.1 製品倉庫の「行」と「ブロック」の区別（Q11・Q12確定）

防火SHの「双方向・2車線・同時すれ違い可能」は、2本を合わせた通路群の確認済み属性として維持する。個別レーンは別要素として管理し、それぞれの一方通行方向は公開済み資料から特定できないため`unresolved`とする。個別方向が確認されても、通路群の確認済み属性を削除・未確定化しない。

- **横一列（1行）単位：双方向・1車線。** AGFはその行を相互に通行できる。1車線であることから対向する2台の同時すれ違いを可能とは推測しない。
- **ブロック単位：双方向の往来が可能。** 複数の行で往来できるという管理単位の説明であり、ブロック全体が物理的に2車線という意味には置き換えない。
- 利用者が述べた「製品倉庫置き場まで2車線」は**横1行を単位に見た説明**。以前の「2車線アプローチ区間から1車線進入区間へ変化する実際の境界を特定する」という解釈を破棄する。道路の物理的な車線減少地点は新たに設定しない。
- WH-X-U／WH-X-Lの既存の概念接続条件、各保管アクセス区間の1車線設定は維持する。WH-E-V／WH-W-Vは各側2本をまとめた参照とし、最新の利用者指示で各側のブロック側を北→南、壁側を南→北へ設定する。旧回答から推測した方向ではない。
- 図示された保管マスは個別の製品パレット置場。行内通路・ロケーション・停止点を別の管理対象とし、行数は計29行で確定。個別接続・実格納方向は後続で確認する。

### 5.2 同一行の02要求・ロケーション予約（Q13・Q14確定）

1. 02の前提である対象PLの包装・ラベル貼付・出口搬出OKが成立した時点で、対象ロケーションと所属行を確認する。
2. **同じ行に既存の置きタスクがある場合、既存タスクの完了まで新しい02タスクを発行しない。** 発行待ち理由と対象PLを保持し、完了後に再判定する。
3. 同行の置きタスクがない場合、ロケーションの空き・予約状況・受入可否を確認する。利用可能なら02発行時に当該ロケーションを予約し、02タスクを発行する。
4. 発行待ちの要求はAGFに割り当てない。予約ロケーションは別のタスクに重複割当しない。荷下ろし完了時の在庫更新は搬送仕様に従う。

上記は**02発行制御**として確認済み。通過するだけのAGFまで同一行から排除する、02発行時に行全体の物理占有を開始する、05にも同一の発行ルールを適用する、といった拡張は未確定。置きタスクの占有開始・解除の厳密なイベント時点や取消時の予約解放は後続で決定する。

### 5.3 同一行・隣接行の干渉

- 同じ行に置きタスクがあれば、少なくともQ14により新規02の発行を保留する。
- **隣接する別の行に2台が同時進入することは可能**だが、近接時には減速する。減速率・距離閾値・開始／解除条件は未確定。
- 既に1車線・交互通行と確認した区間は対向車の同時すれ違いを不可とする。横1行内の横並び通過も不可とし、隣接行の同時進入と混同しない。

## 6. パレタイズ共有走行領域と交通制御

### 6.1 共有領域と初期レーン方向

最新の利用者指示により、PZを物理的に独立した2本の双方向横通路とする旧構造を変更する。**物理的には共有走行領域、交通制御上は2レーン**として扱う。

| 交通レーン | 位置関係 | 通常進行方向 | 占有単位 |
| --- | --- | --- | --- |
| PZ-A1 | 北側・設備側 | **東→西** | 各論理区間1台。共有交差点・接続領域は別途排他 |
| PZ-A2 | 南側・外通路側 | **西→東** | 各論理区間1台。共有交差点・接続領域は別途排他 |

西端と東端だけでレーンを変更する旧制約は使用しない。入口・設備取付け・必要な分岐など、Scenarioのグラフへ明示した接続地点でレーン変更を行う。入口から目的設備へ進むために不要な左方向の迂回や旋回を追加しない。設備別のPGW1～8、PM1～5、OT1～3、包装機HI/HO、整列機AL1～5の個別停止点を維持し、代表共通点へ置き換えない。

既存のPZ南面西SHから進入／南面出口SHから退出、倉庫の通常東SH出入を維持する。倉庫西SHは通常不使用とし、異常時の迂回・入口出口反転は未承認経路として別管理する。通常PZレーンの逆走は許可しない。§6.5の限定予約経路以外へ逆方向例外を広げない。

共有領域・接続・設備前停止点の公開座標は合成描画用であり、実CADの車幅、通過離隔、停止座標、距離を確定しない。

### 6.2 進入前の競合判定と譲り処理

- レーン、区間、交差点、レーン変更部、設備前接続、排他停止点を明示した競合領域として管理し、**次区間へ進入する前**に空きと予約を確認する。同じ排他停止点の現在占有と到着予約は別に管理し、どちらも他車が持つ場合は進入しない。
- 競合時は手前で停止する。既に区間を走行中のAGFを優先し、後からの要求でその車を押し戻したり瞬間移動させたりしない。
- 未進入の競合車同士では積載車を優先し、空荷車が譲る。この交通優先は目的地エリア・バッテリーによるタスク選定とは独立する。
- 同条件の競合は要求／イベント順を用いて決定し、根拠を **`synthetic runtime tie-break`** として履歴・条件へ残す。AGF ID順を現場固有の通行優先にしない。
- 通常停止だけで解消できない場合でも、明示された退避経路を実行可能な車だけを回避候補とする。候補が1台ならその車、両方なら空荷移動車を先に回避させる。架空の退避ノード、表示上近い地点へのワープ、走行中区間の瞬時中断は行わない。
- レーンと共有競合資源は一括取得し、取得できなければ部分予約を残さない。解除、再開、待ち理由、デッドロックを保存済みイベントから追跡する。AGF同士の重複表示や車体貫通で競合を解決しない。

### 6.3 同方向追い越しと荷役姿勢

同方向で移動中のAGFを後方車が追い越すことは原則禁止。明示された同方向グループの論理接続順で前後関係を保ち、同じ接続地点からの同条件要求はイベント順で処理する。グループへの登録時刻だけで、既に前方にいる車の離脱を後方車が妨げない。

荷受け／荷下ろし姿勢へ移行中は、設備前の明示された競合区間を他AGFが先行通過しない。離れた区間まで同じグループ名だけで全面停止させない。フォーク挿入済み荷役になった後は通過候補とするが、方向、1車線占有、設備接続資源、交差点、停止位置等の制約は保持する。フォーク挿入済み状態だけで2台同時占有を許可しない。

### 6.4 搬送01の包装機入口待ち

PGWで荷受け完了後、包装機入口の実在荷と有効予約を入口容量と照合し、受入許可も確認する。入口受渡容量の基準は1PL、内部コンベアの保持容量は5PL、出口受渡容量は1PLであり、内部保持5PLは同時包装5台ではない。

入口を予約できない場合、AGFは積載と搬送01タスクを保持し、**荷受けしたPGW前で包装機方向へ停止旋回してから待つ**。専用状態を `waiting_wrapper_input` とし、一般交通待ちと区別する。別の仮待機場所へ移動せず、待機中に繰り返し向きを変えない。

設備前待機領域は合成トポロジーへ明示し、PZの両レーンを同時に塞がない。少なくとも片側の通常走行経路を残す。ただし待機車の車体を貫通して通過することは許可しない。正式なCAD停止位置・待機姿勢の安全余裕は未確定。

待機車の発進には、入口予約の取得、自車前方の正規レーンと競合領域の空き、横の例外追い越し完了をすべて要求する。入口が空くだけで複数車を同時発進させない。

### 6.5 包装機入口待ちだけに適用する例外追い越し

例外対象は、搬送01の荷受け済みAGFが `waiting_wrapper_input` で完全停止し、発進予定がなく、その車によって正規レーンが物理的に塞がれる場合に限る。通常走行中、低速走行、一般交通待ち、充電待ち、干渉待ちに自動適用しない。通常経路が使える場合も例外を起動しない。

実行するには、明示された経路について以下を満たすこと。

1. 反対レーンに走行中・予約済みの通常AGFがいない。
2. レーン変更開始部、反対レーン区間、待機車横の競合領域、正規レーンへの復帰領域が空いている。
3. 経路上のレーン・区間資源、共有交差点、排他停止点の現在占有と到着予約を確認する。復帰停止点が他車の使用中なら開始しない。
4. 上記全資源を開始前に一括予約し、追い越し中は全行程完了まで保持する。
5. 一時的な逆方向使用は当該予約経路で明示された区間だけに限定する。待機車横を通過後、必ず正規レーンへ復帰して通常方向を守る。

一つでも未成立なら追い越し側が手前で待つ。通常方向で走行中／予約済みの対向車を止めて例外車を優先しない。待機車は横で追い越し中に発進しない。実図の追い越し経路・離隔・レーン変更停止位置が未確認なら生成しない。合成グラフでも明示計画がない場合は例外経路なしとして保持する。

### 6.6 停止旋回・荷役初期値と未確定事項

方向変更時は旋回位置で並進を止め、必要角度を回し終えてから次区間へ進む。固定停止秒数ではなく、Runの角速度から `turnDurationMs = abs(turnAngleDeg) / turnRateDegPerSec * 1000` を求める。必要角度が0度なら旋回イベントを追加しない。

利用者指定の暫定初期値は、旋回12.1deg/s、荷受け姿勢移行0.25分＋フォーク処理0.10分、荷下ろし姿勢移行0.25分＋フォーク処理0.15分、旋回中の電池消費有効。12.1deg/sは0.3m/s・半径1.424mから換算した等価値であり、実測停止旋回速度ではない。いずれも変更可能なScenario条件として保存し、実スペックと区別する。

実旋回位置、実測角速度、減速／再加速、実停止点、車体離隔、干渉検知距離、退避／追い越し経路、シャッター実信号境界は未確定。初期交通方向や利用者指定の暫定値を再び未設定扱いに戻さず、測定されていない物理条件だけを追加確認する。

## 7. 受入条件・更新規則

- 第1段階で`forbidden`の区間は経路探索対象にしない。
- `unresolved`は通行可能扱いにせず、確認待ちを表示する。
- 片方向を確定するまでは、図示の矢印だけで逆方向の可否を推測しない。
- 製品倉庫で双方向2車線・同時すれ違い可能と確認済みの区間はその条件を使用する。1車線・交互通行と確認済みの区間は対向車の同時すれ違いを許さない。横1行内の横並び通過は不可。西2本・東2本の初期方向は各側のブロック側が北→南、壁側が南→北とする。実車離隔や停止寸法は未確定のまま保持する。
- 防火SHは通路群の確認済み属性と個別レーン方向を分離する。個別方向を確認できない間も、通路群の双方向2車線・同時すれ違い可能を取り消さない。
- 西SHは通常モードで経路探索から除外する。東SH故障時モードは既存の迂回・入口出口反転要件を保持するが、切替条件と操作手順が確定するまで経路探索可能にしない。
- PZは共有走行領域の北側レーン東→西、南側レーン西→東を使用し、必要な接続点で明示されたレーン変更を行う。設備の個別停止点を保持し、不要な入口左迂回、車体貫通、排他領域の二重占有を許さない。
- 02は同じ行の既存置きタスクが完了する前に発行しない。発行時に空き・予約を確認し、利用可能なロケーションを予約する。
- 停止旋回、進入前競合判定、同方向追い越し原則禁止、局所荷役位相、PGW前包装機入口待ち、限定追い越しをイベント・占有回帰で確認する。例外追い越しは明示経路の全資源一括予約と通常対向車の優先を必須とする。実座標・実離隔・実測角速度が未確定の間は実機相当の安全性や確定ETAを主張しない。
- 変更ごとに改訂番号と対象区間を記録し、ユーザー確認済み事項を繰り返し未確定扱いに戻さない。
