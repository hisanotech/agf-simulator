# 04. 通常搬送03 仕様書 v1.1

**独立仕様書**／関連：[全体](00-overview.md)・[設備](01-equipment.md)・[AGF](07-agf.md)

## 1. 目的・対象

空パレット残数が補充閾値に達したマガジンへ、在荷10枚の空パレット整列機から一山を補充する。マガジン側の補充必要状態、整列機の在荷、03タスクの発行、AGF搬送、マガジンへの実投入は別状態として管理する。

| 項目 | 仕様 |
| --- | --- |
| タスクID | 03 |
| 搬送元 | **在荷10枚で搬送可能な整列機**（5台から選択） |
| 搬送先 | 補充必要状態のマガジン（5台から対象を指定） |
| マガジン補充契機 | 対象マガジンの残数が**3枚になった遷移** |
| 03発行条件 | 補充必要状態のマガジンがあり、かつ在荷10枚の利用可能な整列機が1台以上あること |
| 搬送量 | **一山10PL** |
| 完了条件 | 残数確認・投入許可後の10PL投入実績 |
| 起点への移動 | AGFの**現在位置 → 整列機 → マガジン** |
| 供給元対応 | 固定1対1ではない |
| 初期状態 | マガジン5台は各10枚、整列機5台も各10枚装填済み |

## 2. 入力データ

`taskId`, `magazineId`, `magazineQuantity`, `refillNeeded`, `refillPending`, `alignerId`, `alignerQuantity`, `alignerReady`, `alignerPermission`, `magazinePermission`, `agfId`, `refillBatch`。

基準Runではマガジン・整列機とも全機10枚から開始する。マガジン最大容量、個別設備位置、搬送時間は別設定とし、未確認値を固定しない。

## 3. 初期状態

シミュレーション開始時は03に関してニュートラル状態とする。

- マガジン5台：各10枚
- 整列機5台：各10枚
- 03タスク：0件
- 整列機予約：なし
- マガジン補充要求／補充中：なし
- 設備異常：シナリオで明示されない限りなし

整列機の10枚は「搬送可能な一山」として扱う。時間経過だけで数量を変更しない。

## 4. 処理フロー

1. パレットマガジンで空パレットを実際に払い出し、残数を更新する。
2. 残数が**ちょうど3枚に達した遷移**で、当該マガジンを「補充必要」にする。
3. 利用可能な整列機を確認する。
4. **在荷10枚の整列機が1台以上ある場合のみ03タスクを発行する。**
5. 全整列機が空の場合は03タスクを発行せず、マガジンの「補充必要」状態だけを保持する。
6. 作業者が整列機を手動補充した場合、補充必要状態のマガジンを再評価し、03発行条件が成立すればタスクを発行する。
7. 実行可能なAGFを割り当てる。エリア優先ありでは、荷下ろし先である対象マガジンの目的地エリアにいる実行可能AGFを優先する。
8. AGFが現位置から整列機へ空走し、荷受け許可を確認する。
9. **10PL荷受け完了時点で整列機の在荷を10→0とし、空状態へ遷移する。**
10. 空になった整列機は、作業者が再補充するまで03の供給元候補にしない。
11. AGFが対象マガジンへ実搬送する。
12. 投入直前にマガジン残数を問い合わせ、投入許可と受入条件を確認する。
13. 10PL投入完了の実績を登録し、そこで初めてマガジン残数を+10する。
14. マガジンの補充必要／補充中状態を解除し、AGFを解放する。

## 5. 整列機の手動補充

整列機は自動回復させず、画面操作による手動補充とする。

### 個別補充

各整列機に「補充」操作を設ける。

- 空の整列機を10枚装填済みへ戻す。
- すでに10枚ある整列機へさらに10枚加算しない。
- 補充操作後、その整列機を03供給候補として再評価する。
- 補充必要マガジンが存在する場合は03発行条件を再評価する。

### 全機一斉補充

「全整列機を補充」操作を設ける。

- 5台すべてを10枚装填済み状態にする。
- すでに10枚の整列機は10枚のままとし、20枚にはしない。
- 補充後、未処理のマガジン補充必要状態を再評価する。

補充操作はイベント履歴に残し、個別補充か一斉補充かを識別できるようにする。

## 6. 状態遷移

マガジン側は、
`NORMAL → REFILL_NEEDED → TASK_ISSUED → REFILLING → NORMAL`
とする。

整列機側は、
`LOADED_10 → RESERVED → PICKED_EMPTY → MANUAL_REFILL → LOADED_10`
とする。

**整列機が空のため供給元が存在しない場合、03タスクを先に発行して `WAIT_SOURCE_READY` にしない。** マガジンの `REFILL_NEEDED` を保持し、供給元が手動補充された時点でタスク発行を再判定する。

## 7. 在庫・占有の規則

- 「残数3枚」という状態を毎秒評価して新規03を増殖させない。
- マガジンの在庫減算は実際の空パレット払い出しイベントによる。
- 整列機は在荷10枚のときだけ03供給元候補にできる。
- 整列機から10枚を荷受けした時点で在荷0枚とする。
- 空の整列機を別の03へ割り当てない。
- 同じ整列機の10PLを複数03へ重複予約しない。
- 全整列機が空なら03タスクを発行しない。
- 補充量+10は**マガジン投入完了後**。投入許可が出た段階ではまだ加算しない。
- マガジン上限未確定時は満杯可否を断定せず、確認不能の旨を記録する。

## 8. 出力・履歴

`requestedAt`, `magazineId`, `quantityAtRequest`, `alignerId`, `alignerQuantityBeforePickup`, `pickedAt`, `alignerQuantityAfterPickup`, `agfId`, `quantityBeforeRefill`, `permissionAt`, `completedAt`, `quantityAfterRefill`, `waitReason` を記録する。

整列機手動補充については、`alignerId`, `operationType`（individual/all）, `quantityBefore`, `quantityAfter`, `operatedAt` を履歴に残す。

## 9. 受入条件・未確定

- 初期状態でマガジン5台・整列機5台が各10枚である。
- 残数3枚到達時に補充必要状態を1回だけ成立させる。
- 在荷10枚の整列機が存在する場合だけ03タスクを発行する。
- 全整列機が空の場合、03タスク件数が増えない。
- 空の整列機を03供給元に選ばない。
- 03荷受け完了後、その整列機は0枚になる。
- 個別補充で対象整列機だけ10枚に戻る。
- 全機一斉補充で5台すべて10枚に戻る。
- 補充操作は加算ではなく10枚への復帰であり、20枚にしない。
- 手動補充後、補充必要マガジンがあれば03発行を再評価する。
- 搬送OK前の荷受け、投入許可前の荷下ろし、完了前のマガジン+10を拒否する。
- AGFの二重割当、整列機の二重供給、マガジン残数マイナスを拒否する。
- **未確定：** マガジン最大容量、供給元選択の詳細な優先順位、荷役・走行時間。
