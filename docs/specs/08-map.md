# 08. 全体マップ仕様書 v1.8

**独立仕様書**／関連：[全体](00-overview.md)・[設備](01-equipment.md)・[AGF](07-agf.md)・[走行経路の指定ガイド](../route-annotation-guide.md)・[AGF通行・車線仕様書](09-traffic.md)

> 目的は「設備の位置関係・移動経路・AGFの現在状態を、簡易2D平面図で再現すること」。本書は画面・データ構造・状態連携の仕様であり、未確定の経路や設備座標を確定させるものではない。実図・現場画像・原本の名称・実座標は公開リポジトリへ保存しない。

## 1. 対象範囲

- 画面上側からパレタイザエリア、外通路、製品倉庫の3帯とし、左＝西、右＝東の図面方向を採用する。2建屋は外通路で分け、壁を共有させない。
- マップ上に設備、パレット置場、AGF、荷役停止点、待機・充電地点、シャッター、経路、状態を表示する。
- **シミュレーターの最終レイアウトはCAD図に準拠する。** 設備・通路・シャッター・保管区画・個別荷役位置の位置関係をCAD図と照合し、矛盾のある仮配置を確定レイアウトとして使わない。現在の公開用簡略図は概念図であり、CAD一致を証明しない。
- 2Dマップとイベント駆動エンジンは分離し、マップのアニメーションを独立した搬送完了判定にしない。
- 設備レイアウト編集・経路データの取込みは将来の開発対象。現時点のコードハーネスに実装済みと解釈しない。

### 3.1 製品倉庫の系列割当表示

製品倉庫の各行について「どの系列を置けるか」をマップと製品倉庫詳細ダイアログの両方で確認できるようにする。

- GWI～GWVIIIは系列ごとに一貫した識別色を使用する。
- SPECIALは通常系列と区別できる専用色／表現を使用する。
- 未割当行を正式に許容し、未割当は中立色で表示する。
- 色だけに依存せず、行ラベルまたは凡例に系列名／SPECIAL／未割当を文字表示する。
- マップとダイアログで同じ系列は同じ色・同じ凡例を使用する。
- 色分けのためにラック寸法、行数、列数、通路、設備位置を変更しない。
- 未割当行は表示上存在するが、製品配置候補には使用しない。
EB2南側の待機2・充電2・整列機5は既存の東側主通路へ論理接続し、空パレ置き場はAGF進入禁止。詳細と根拠区分は[倉庫概念契約](../warehouse-layout-contract.md)に集約する。

## 4. 経路・エリア通行制約

走行可否を最初に確定し、その後に各区間の方向・車線数・同時すれ違い条件を確認する。詳細台帳は[AGF通行・車線仕様書](09-traffic.md)を正とする。双方向通行と2車線を同義としない。

### 4.1 確認済みの基本ルール

- パレタイザエリアは南面の西SHから進入し、南面の出口SHから退出する。旧パレタイザ東SHは完成概念図へ残さない。
- 製品倉庫は通常時に東SHから出入し、西SHを通常走行経路に含めない。東SH故障時の西SH迂回とパレタイザ入口・出口反転は既存運用として保持するが、切替条件・操作手順・物理経路は未確定であり経路探索へ流さない。
- 通常運用の外通路は、倉庫東SHから西へ進んでパレ西入口SHへ至る進入関係と、パレ出口SHから南へ直進して倉庫東SHへ戻る関係を分けて保持する。外通路を中央防火SHへ接続しない。
- 製品倉庫の壁に平行な主通路は**西2本・東2本**で、保管ブロックと中央壁の間に置く。個別主通路の方向・車線数・同時通過条件は未確定。中央壁の自由横断は不可で、防火SH2か所を介する。各防火SHの通路群は確認済みの双方向2車線・同時すれ違い可能を維持し、個別レーン方向は確認できるまで未確定として別管理する。各保管行は**双方向1車線・横並び通行不可**。[倉庫概念契約](../warehouse-layout-contract.md)と[通行台帳](09-traffic.md)を参照。
- パレタイズエリアの走行通路1・2は各々全区間通行可能で、西端・東端の両方で接続する。PGW・PM・包装機、OT1～OT3はすべて通路1から接続する。各通路は双方向・1車線で、**通路1・2の組合せを双方向2車線として扱う**。西端・東端接続と設備・仮置き場への取付けも双方向・1車線。P5～P10では同時すれ違い「可能」と回答済みだが、各1車線区間内部での通過形態・排他制御は未確定。詳細は[AGF通行・車線仕様書](09-traffic.md)を正とする。
- 01・02は上記の基本的な入退場ルールを使用する。03は倉庫東側から出てパレタイザ西側から進入する。
- パレタイズエリアでは干渉制御をAGF側で行い、タスク実行中のAGF同士が互いに通行できるよう制御する。同時すれ違い「可能」という回答を維持しつつ、具体的な通過形態・無停止通過の可否・譲り合い方法は未確定。
- これらは**通行制約**であり、通路上の具体的な線・曲がり角・旋回点・各荷役停止座標を確定するものではない。

### 4.2 走行グラフの定義

- **Node：** \`nodeId\`、\`type\`（荷役／シャッター前／交差点／旋回／HP／ロケーション）、\`areaId\`、\`x,y\`、\`heading\`、\`status\`、\`sourceNote\`。
- **Edge：** \`edgeId\`、\`fromNodeId\`、\`toNodeId\`、\`direction\`、\`distance\`、\`speed\`、\`passable\`、\`shutterId\`、\`status\`。
- **Route：** \`routeId\`、\`taskType\`、\`originNodeId\`、\`destinationNodeId\`、順序付き\`nodeIds\`、\`loadState\`（空走／積載）、\`status\`、\`revision\`。
- 座標は表示用の基準画像上に正規化して扱う。距離・速度・所要時間は、承認済みの縮尺・経路・設定値が揃ってから算出する。
- 双方向区間でも、逆向きの通行許可を推測しない。各Edgeの通行向きを明示する。
- 一つのRouteは荷受け前の**空走区間**と、荷受け後の**積載区間**を分けて持つ。充電移動は別Route。
- 走行制約や停止点変更時は\`revision\`を更新し、過去の結果がどの版で計算されたか追跡できるようにする。

### 4.3 経路の確定区分

| status | 表示・処理 |
| --- | --- |
| \`confirmed\` | 承認済みのノード・エッジとして描画。距離・速度等の入力が揃えば所要時間を計算可能 |
| \`provisional\` | 破線・「仮」ラベルで表示。デモ用の移動補間は可能だが、実搬送時間・実距離として表示しない |
| \`unresolved\` | 点または区間の詳細未定。移動結果を推測して確定値として計算しない |
| \`disabled\` | 走行不可。経路候補から除外する |

AGF4台の位置を単純な直線補間だけで移動させる場合も、実通路の存在・通行可能性を証明したことにはならない。

## 6. 停止・旋回・荷役

- 各シャッターは通行要求、開／通行可能、通過、解除をイベントで追跡する。停止点はシャッターごとに指定し、現時点では未確定として記録する。
- 荷受け点と荷下ろし点は設備中心座標で代用せず、個別の\`stopNodeId\`を持つ。
- 旋回点は当面、交差点／曲がり角に仮設定。旋回可能な寸法、向き、干渉などは未検証。
- 車両の姿勢を表示する場合は進行方向と荷役姿勢を分ける。停止姿勢が未指定なら「未確定」と表示する。
- 交差点やシャッターの占有・排他、衝突判定を実運用相当とするには、区間占有ルールと実ルートが必要。未確定段階で「安全にすれ違える」と断定しない。

## 7. 2D画面と操作

- マップは拡大縮小・パン・全体表示・AGF選択・設備選択に対応する設計とする。
- レイヤー表示切替：設備名、在荷・容量、荷役点、シャッター、旋回点、走行線、仮設定、AGF軌跡、倉庫系列割当。
- 選択したAGFの\`agfId\`、タスク種別・ID、積載パレット、残量、状態、現在ノード、次停止点を表示する。
- 選択した01～05の経路は色または線種で区別し、荷受けまでの空走と積載後の走行を識別する。
- 実行中のイベントから表示時刻の位置と設備状態を復元する。時刻シーク・倍速でもイベント順序と履歴が変わらない。
- 確定経路は実線、仮経路は破線、走行不可は非表示または禁止表現とする。凡例を常時確認できるようにする。
- 画像背景が表示できなくても設備・停止点・車両の識別ができる簡略マップを用意する。

## 8. データと公開範囲

DXFを用いない先行成果として、[論理マップJSON・2D概念図](../logical-map.md)と確認済み概念リンクの検証処理を追加済み。これは**実寸図面を再現したものではなく、概念経路の確認用**。未確定リンクはルーティングに使用せず、個別ロケーションまでの全区間走行時間・ETAを算出しない。

実CADからの取込みは[DXFマップ取込仕様](../map-dxf-pipeline.md)に従う。DXFはmm・明示原点・承認されたレイヤー対応で読み込み、注記・寸法・ハッチを除外する。**図形の抽出と走行グラフの確定は別工程**で、エリアをまたぐ通行は明示したゲートIDで接続する。任意グリッドは明示された走行可能閉ポリゴンから作る幾何学的候補であり、車線・干渉・シャッター条件・パレット在荷を自動確定しない。

DXFは受領・非公開領域で解析済みであり、選択したCAD-native図形を私有データへ抽出している。ただし**単位と原点の検証、参照ブロックの展開、通行線・停止点の照合が未完了**のため、mm確定の現場全体マップおよび01～05の実物理経路は未生成。公開リポジトリには抽出ツールと合成データのみを置く。

表示用\`Layout\`と、機密区画に保持する実配置データは別管理する。公開コード側は入出力スキーマと**架空の合成レイアウト**だけを保持する。提供ファイル名、実図、実座標、実走行距離、顧客・現場の識別情報を登録しない。ユーザーが確認した図面上の論理ルールを実座標・安全仕様と混同しない。

## 9. 受入条件

1. 図面方向・設備区分・個別荷役点を表示し、異なる停止点をまとめない。
2. 01～05、空走／積載、充電移動が別のRouteとして識別できる。
3. 各エリア入退場制約・禁止シャッターを守る。誤った経路は拒否・保留する。
4. シーク後のAGF位置・状態と、同時刻のイベント履歴が一致する。
5. 仮・未確定経路から確定距離・ETA・安全性を主張しない。CAD図との照合前の模式図を、レイアウト準拠済みとして扱わない。
6. 経路・設備配置を更新しても、過去Runの\`revision\`と使用設定が追跡できる。

### 9.1 概念表示の受入条件 G01～G17

G01～G17は[最新レイアウト修正指示](../製品倉庫レイアウト・AGF通行仕様書.md#5-全体図を描くときの拘束条件禁止事項)を正とし、`data/reference-logical-map.json`の`layoutAcceptance`で機械検証する。対象は3帯、南面SH、南北軸整列、外通路の通常動線、パレタイズ2通路、OT配置、倉庫4主通路、防火SH、802PL、EB2南側設備、柱前待機候補、空パレ置き場進入禁止である。

これらは**概念図上の相対関係の受入条件**であり、`coordinateBasis=schematic-relative-only`、`physicalCoordinatesConfirmed=false`とする。実CADの開口中心、寸法、停止点、旋回点を架空の数値で検証しない。実CAD座標の受入は、縮尺・原点・対象点の承認後に別テストとして追加する。

## 10. 未確定事項

系列8か所の番号と個別停止位置、全走行線、各シャッター前停止点、旋回位置・姿勢、倉庫各ロケーションの実座標・正式ID対応、区間別距離・速度・荷役時間、分岐の優先／排他、仮置き場停止点の座標。確定方法は[経路指定ガイド](../route-annotation-guide.md)に従う。
