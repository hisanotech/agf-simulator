# 確定済み通行仕様に基づく搬送エリア論理マップ v0.4

| ファイル | 目的 | データ区分 |

| [reference-logical-map.json](../data/reference-logical-map.json) | エリア、通行区間、方向、車線、論理接続、設備入口、01～05の搬送元／先、発行制約 | 利用者確認済みの**抽象的な関係**。物理寸法や個別停止点ではない |

| [logical-map.mjs](../src/map/logical-map.mjs) | JSON検証と確認済み論理リンクの探索 | **概念経路だけ**。実走行経路・ETAは算出しない |

元図・実CAD形状、ファイル名、実座標、画像そのものは公開GitHubへ保存していない。DXFを用意しなくても、**確定した通路間の論理接続をシミュレーターへ渡す**段階まで進められる。追加で提供されたDXFから私有のCAD-native形状を抽出したが、公開用の模式図には実図の座標を混入させていない。単位・原点と物理ノードが未確認のため、抽象グラフと実CAD図形の結合は未実施。

## 2. このJSONの構造

- areas：パレタイズ（PZ）、製品倉庫（WH）、エリア間（INTER）。
- corridors：区間ID、エリア、進行方向、車線数、同時すれ違いの回答、通行可否。geometryStatus はすべて not-measured。
- corridorGroups：PZは1つの共有走行空間の対向2論理レーン。北は東→西、南は西→東。物理分離も両端だけの接続も設けない。
- links：通路同士の概念接続。confirmed と unresolved を明示し、別の reviewState が一致しなければ確定扱いできない。
- interfaces：PGW8、PM5、包装機1（投入／回収2インターフェース）、OT3、整列機5、充電器2、HP2、倉庫の個別ロケーション。
- layoutAcceptance：G01～G17の概念図上の相対関係。実CAD座標の検証とは分離する。
- accessRules：通常時の倉庫東SH入出／西SH不使用、東SH故障時の未確定な西SH迂回、パレタイズ入口・出口反転要件、02の同一行置きタスク保留と発行時ロケーション予約、隣接行の減速など。
- taskRoutes：01～05と充電移動の搬送元・先、未確定箇所。
- unresolved：個別停止位置、実通路へのゲート取付け、エリア間詳細、各ロケーションの正式ID・実行接続、区間距離・旋回・交通制御詳細。

coordinateSystem: none、hasActualSiteCoordinates: false、hasMeasuredDistances: false により、**JSON内の概念区間IDと実CADのノード座標を混同しない。**

## 3. 通行確認を反映した部分

### パレタイズエリア

PZ-A1（北・設備側、東→西）とPZ-A2（南・外通路側、西→東）は、同一の走行可能空間に設定した対向2論理レーンであり、物理的に分離された通路ではない。旧 `PZ-CON-W` / `PZ-CON-E` と「両端だけで接続」という解釈は廃止する。設備前・入口・出口・必要な合流点を明示的なノードとエッジで接続する。入口から共有空間へ直接入れ、設備へ進む前の共通の左迂回・余分な旋回を要求しない。個別PGW／PM／HI・HO／OT停止点を維持し、設備位置を動かして経路を合わせない。

公開合成運行グラフには設備前のレーン変更・排他資源と方向を明示する。図上の座標・モデル距離は合成値であり、現場の車線幅や旋回可能性の確認ではない。通常の同方向追い越しは禁止し、包装機投入待ちの完全停止車だけを対象とする明示的な例外計画は通常方向制約と分離する。

公開合成グラフの交差は、描画線が重なるだけの状態を許容しない。防火SH接続は既存の東西主通路の接続点で分割し、外通路の戻り動線は既存の入口動線の旋回点を共有停止点として通る。整列機への各枝とサービス通路の合流点にも排他を宣言する。分割した距離は元の合成モデル距離を明示配分し、図上の線長から実距離を算出しない。合成防火SHの交互通行区間は分割後も共通のレーン資源と明示された一括予約区間を持ち、対向車が占有する出口へ向かって途中接続点まで先に進まない。これは確認済み防火SH通路群の2車線属性と区別した保守的なテストモデルであり、実レーン方向を確定しない。

### 製品倉庫

壁沿い主通路は西2本・東2本。旧WH-E-V／WH-W-Vは各側の通路群への抽象参照とする。最新ユーザー指示の初期交通方針は、両側とも保管ブロック側が北→南、中央壁側が南→北。車線幅・実分岐・同時通過条件は未確認。上下の防火SHは、通路群の双方向2車線・同時すれ違い可能を確認済み属性として維持し、個別2レーンの方向を未確定として分離する。壁の任意横断は認めない。保管区画アクセスは双方向1車線・交互通行、各行は双方向1車線・横並び通過禁止。主通路の初期方針で既存の設備枝・サービス枝・外通路の方向を上書きしない。倉庫西SHは通常経路から除外し、東SH故障時の迂回要件だけを未実装の運用契約として保持する。

[倉庫概念契約](warehouse-layout-contract.md)に基づき、802保管位置、東の空列、4本の主通路、EB2南側の待機2・充電2・整列機5・進入禁止の空パレ置き場をwarehouseLayoutに定義する。東側主通路群から南側設備へのアクセスは確認済み。個別主通路割当・停止座標は未確認。

同じ行に既存の置きタスクがある間は新しい02を発行しない。02の発行時に搬送先ロケーションの空き・予約状況を確認し、利用可能な位置を予約する。個別位置の実座標と正式IDの対応は未確定で、架空の倉庫ロケーションを実施設位置として列挙しない。

## 4. 経路探索に使える範囲

findConceptualPath は**両端が通行可能で、リンクが確認済み**の場合に限り、通路IDの順序を返す。例として、パレタイズ通路2→通路1→設備側、倉庫東縦通路→上段／下段接続→西縦通路の**概念経路**は検証できる。

一方、包装機出口から個別倉庫位置へ至る**完全な物理経路はまだ返さない**。パレタイズ出入口と通路の正確な取付け、エリア間接続、シャッター停止点、倉庫個別行・個別ロケーションへの接続が未確定だからである。未確定リンクを仮に通して所要時間や安全性を算出しない。

このグラフのノードは実座標ではなく通路区間IDである。個別停止点・旋回点・通路のノード／エッジは、別の物理グラフとして確認する。公開合成グラフ用の走行・交通エンジンは実装済みだが、抽象制約やCADレビュー候補を自動昇格させない。三層の境界と合成モデルの契約は[合成運行グラフ・交通制御契約](operational-topology-contract.md)を参照する。

## 5. 検証方法

    npm run check:map
    npm run check

テストは、G01～G17、通路1・2の合計車線数と各通路の車線数、防火SHの通路群／個別レーン分離、通常時の西SH除外と未確定な異常時迂回、未確認の物理エリア間通行を勝手に許可しないこと、02の同一行保留・発行時予約などを確認する。

## 6. 後続に必要な情報

実行可能な01～05の完全な経路と3時間シミュレーションの移動時間を算出するには、個別荷役停止点・倉庫ロケーションと各行の対応、エリア間通路の接続・各SHの通過停止点、区間距離／速度／旋回条件を追加確認する。DXFによる実寸形状の取込みは[別パイプライン](map-dxf-pipeline.md)として継続可能だが、論理マップを作り始めるための前提条件ではない。
