# 区間レビュー・走行候補グラフ契約（M2 / 未完成）

本書は**公開可能なコードの使い方のみ**を説明する。元DXF、実座標、現場の図面画像・レイヤー名、レビュー結果JSONは公開リポジトリに置かない。関連: [実装計画](implementation-plan.md) / [経路図の指定](route-annotation-guide.md) / [進捗Issue #2](https://github.com/zony21/agf-simulator/issues/2)。

## 目的と区別

- `private-route-annotations-v1` は元の**表示下書き**。`draft-only` / `routable=false` / `physicalEtaAllowed=false` を維持する。編集した線を勝手に昇格させない。
- `private-segment-review-v2` は同一SVGのSHA-256、viewBox、ノードID・タイプ・正規化座標、経路の区分・順序に紐づく**別の確認台帳**。点の位置・役割、共有点での接続、区間属性を独立して確認する。線を動かす／経由点を増減・置換する／点種別や搬送区分を変更すると以前のレビューは失効する。Undo・Redoでも失効した確認は自動復活しない。
- `reviewed-topology-v2` は点・接続と区間の確認が揃い、搬送／充電の区分がある区間だけを採録する**位相グラフ**。未確認点・共有接続、未割当の参考ガイド、通行不可、未確認区間は含めない。
- 上記グラフも `physicalEtaAllowed=false` / `trafficReady=false` / `operationalRoutingReady=false`。距離の単位照合、車体幅・旋回余裕、実シャッター信号、区間の排他制御を証明しない。現場の安全認証ではない。

## 画面操作

1. AGF図形を除外済みの非公開SVGを端末内で読み込み、同じ画像ハッシュの下書きJSONを読み込む。
2. **最初に参考線と停止／旋回／荷役点の位置を直す**。図上点を選択して「選択点の種別を変更」で役割を修正できる。一般停止は`stop`、倉庫ロケーションは`warehouse_location`とし、充電・荷役・旋回・シャッター点と区別する。
3. 別経路の点と接続する場合、経路とその点を選び、既存点を明示指定して「選択経路点を既存点に置換」を使う。選択経路だけが既存点IDを参照し、他経路や点自体は移動しない。**同座標・近接・線の交差からは接続しない**。表示が変わった区間を図上で再確認する。
4. 「点・共有接続・区間のレビュー」で各点の位置・役割を申告する。複数経路が同じIDを使う点では、表示した**全経路がその点で接続する**ことを別に申告する。これが未確認なら、その点を使う区間はグラフから除外する。
5. 区間の通行可否を申告。通行可の場合のみ、方向・車線数・シャッター有無を**個別に指定**する。同時通過の判断が未確定なら「未確認」のままにする。
6. シャッター制御区間は設備IDと、許可する方向ごとの`shutter_wait`型の進入点を指定する。始点→終点には始点、終点→始点には終点の停止点が必要。双方向は両端の異なる停止点を指定する。この契約では**待機点で区間を分割して登録**する。無関係な別点や反対側の点を待機点に代用しない。位置や信号の仕様を推測で追加しない。
7. 非公開の確認台帳JSONを保存する。同じCAD画像・同じ点・同じ経路の場合だけ読込を許可する。
8. 「通行候補グラフJSON保存」で点・共有接続・区間の確認が揃った候補だけを出力。この候補は距離・速度・交通資源がないため、シミュレーションへ直接接続しない。区間走行エンジンは[公開合成運行グラフ](operational-topology-contract.md)で独立検証する。

## ソフトウェア契約

`src/map/reviewed-topology.mjs` は次の独立した純粋関数を提供する。

| 関数 | 責務 |
| --- | --- |
| `createSegmentChecklist(annotation)` | 全点・共有接続・区間を未確認で初期化。単独点の共有接続のみ`not-applicable`。自動承認はしない。 |
| `setNodeReview(annotation, checklist, value)` | 点の位置・役割確認と、同じIDを使う全経路の接続確認を検証。 |
| `setSegmentReview(annotation, checklist, value)` | 1区間の明示入力を型・既存点で検証。 |
| `validateSegmentChecklist(annotation, checklist)` | 同一画像／下書き／点順序を照合し、重複・欠落・矛盾を拒否。 |
| `importSegmentChecklist(annotation, checklist)` | v2を検証、またはv1を再確認前提で移行。失効した区間IDを返す。 |
| `buildReviewedTopology(annotation, checklist)` | 未確認点・共有接続・区間、通行不可・参考ガイドを除外し、距離なし位相グラフと除外理由を返す。 |
| `validateReviewedTopology(graph)` | JSON読込後も、点と区間の確認状態、ID重複、端点、区分、方向、車線、ゲート待機点、非物理フラグを検証。 |
| `findReviewedTopologyPath(graph, fromId, toId, {taskType, phase})` | 搬送区分・空走／積載／充電区分を必ず指定して方向探索する。別タスクの線を暗黙連結せず、所要時間と交通許可は常に未提供。 |

`access`, `direction`, `laneCount`, `simultaneousPassing`, `gate` を独立属性とする。**双方向＝2車線／同時すれ違い可**とは解釈しない。通行不可・未確認なら進行方向等の通行属性を与えず、完全確認されていない通行可申告も受け付けない。シャッター制御に必要な待機点は単なるウェイポイントを代用しない。`forwardWaitNodeId`／`reverseWaitNodeId`は許可方向のみ指定し、不許可方向は`null`とする。

探索は辺数最小のBFS。同じ辺数ならエッジIDの辞書順で処理し、JSON配列順には依存しない。これは**開発上の決定性ルール**であり現場の経路優先順位ではない。未知の方向値を双方向扱いせず、未知のタスク・空走／積載／充電の組合せも拒否する。グラフから除外済みの端点はエラー、存在する端点間に対象区分の経路がなければ`null`。出力は署名付き承認ではなく、入力した利用者申告の構造検証である。

## 旧台帳の移行と根拠区分

- v1は画像・点・経路を従来どおり照合した後、有効な区間申告を引き継ぐ。点の位置・役割と共有接続はv1に確認欄がなかったため**すべて未確認**とする。
- v1のゲート待機点が進入側端点に一致する片方向区間は保持する。無関係な点、反対側、双方向で片側しか登録されていない区間は未確認へ戻し、対象IDを画面に表示する。
- v1位相グラフは探索に直接渡せない。台帳を移行し、点・共有接続と必要な区間の再確認後にv2を出力する。
- この改修は仕様08・09の点／役割区別、通行確認、未確定除外を実装する。方向別端点でゲート区間を区切る形式と同率探索順は**ソフトウェア契約**であり、現場の停止点・運用・実距離を新たに確定するものではない。公開テストは合成データのみ。

## 回帰テスト（合成データのみ）

`npm run check` で、未確認点・接続・区間／通行不可／参考ガイド除外、同座標でも別IDなら接続しないこと、方向・タスク・空走／積載の制御、点移動／種別変更／区間分割／接続変更／区分変更による失効、方向別シャッター待機点、旧台帳移行、壊れたJSONグラフ、同率探索の決定性、距離／ETAなしを確認する。実図面由来のテスト入力は公開リポジトリに置かない。

## 次工程

- M1：実図面の初期参考線と設備別停止点の非公開レビュー。
- M2：実際の共有接続、通行可否・方向・車線・シャッター運用を確認し、実走行用の根拠を持つトポロジーにする。
- M3：合成グラフで検証済みの区間移動イベントへ、縮尺確認済みの距離／速度を持つ承認データだけを接続。
- M4：合成グラフで検証済みの予約制御へ、確認済みの排他・すれ違い・実シャッター通行条件だけを接続し、運転・安全判断とは分離する。
