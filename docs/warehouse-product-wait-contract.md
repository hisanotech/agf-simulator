# 製品属性・倉庫配置・HP復帰の追加契約

更新: 2026-10-01。利用者の追加指示をローカル実装へ統合した契約。実CAD・実設備の受入、公開承認とは別である。既存入力の再現性を維持し、追加仕様は `warehousePolicy` / `productStreams` / `postTaskPolicy` を明示したシナリオで有効にする。

## 根拠と未設定の扱い

利用者確認済みの論理ルールは、802PL、全8系列の専用行、共通特注領域、奥詰め方向、下段満載時だけの上段利用、待機場所への復帰中の新規割当禁止、充電優先である。さらに初期配置時はHP1・HP2・充電場所1・充電場所2をAGFの置き場として使用してよい。充電場所への初期停止は充電そのものを意味せず、充電器占有とも分離する。**通常運転の待機場所は製品倉庫内の4か所（HP1・HP2・柱前東・柱前西）であり、パレタイズエリアには通常待機場所を設けない。AGFごとの専用待機場所は設けず、帰還時に `HP1 → HP2 → 柱前東 → 柱前西` の順で空いている場所を選ぶ。** 系列別の実際の行割当、行優先順位、ブロック間隣接は未確定。柱前待機場所の相対位置は、西側がWB2とWB3の間の空き領域の東寄り、東側がEB1とEB2の間の空き領域の西寄りとして確認済みである。

UIの追加仕様シナリオでは、AGFごとの固定復帰先を入力しない。通常待機先は共通の優先順位 `HP1 → HP2 → 柱前東 → 柱前西` から動的に選定する。初期在庫は空。既存デモの固定ロケーション・サンプル在庫は旧モデルとして残す。

## 入力・履歴

| 入力 | 内容 |
| --- | --- |
| パレット | `sourceLineId`、`productType: normal/special`、`loadType: full/partial`。01・包装・02・04・05を通じ保持 |
| `productStreams` | 8系列×4種別の `enabled`、`intervalMin`、`startOffsetMin`。初期ONは普通満載のみ |
| `warehousePolicy.rowAssignments` | 行ID、用途 normal/special、普通銘柄の系列ID。**未割当行は定義しなくてよい**。割当済み行は1行1用途 |
| `warehousePolicy.rowPriority` | 複数行を持つ用途ごとに、割当行を重複なく明示した配列 |
| `initialPallets` | 初期在庫の属性。下段なし上段、端数上段、用途不一致、重複IDは拒否 |
| 通常待機場所選定 | AGF固定割当は持たず、帰還開始時に `HP1 → HP2 → 柱前東 → 柱前西` の順で、未占有かつ未予約の最初の場所を選定する |

通常の系列別搬出間隔の初期値は、設備能力100%を前提にした理論パレット排出タクトとし、GWI 17.2、GWII 36.5、GWIII 36.5、GWIV 22.9、GWV 25.3、GWVI 21.5、GWVII 36.5、GWVIII 36.5 min/PL を使用する。普通満載のみONという既存デフォルトは維持し、端数・特注は明示的に有効化した場合だけ生成する。これらの間隔は実PLC履歴ではない。実態の最短払出頻度は GWI 3.1、GWII 1.6、GWIII 1.6、GWIV データ無、GWV 2.3、GWVI 2.7、GWVII 1.4、GWVIII 1.5 PL/hr で、長時間継続せず最大約90分までの参考実績として別扱いする。

発生時刻は整数ミリ秒に丸めた「間隔＋ずらし」、以降は一定間隔。ランダム性を導入しない。OFF種別は発生しない。外部生産イベントと間隔入力を同時使用しない。外部イベントの `sourceLineId` は `lineId` と一致が必要。

イベント・タスク・CSVに属性、配置先、ブロック・行・列・段、入庫結果、保留理由を残す。CSVの先頭行には再現用シナリオ全体を保存する。特注でも元の系列情報を維持する。

## 入庫選定

1. 普通は元系列、特注は共通SPECIALだけを候補にする。**全系列に最低1行は必要**だが、倉庫の全行を何かへ割り当てる必要はない。未割当行を許容する。特注ONなら特注用行が必須。
2. 同じ用途は同一ブロック内で連続した行に限定する。未割当行を同一系列の割当行の間へ挟んで連続性を崩さない。ブロックを跨ぐ入力は「連続条件未確定」で拒否する。
3. 複数行の優先順位が未入力なら `ROW_PRIORITY_UNRESOLVED` で保留する。行ID順を現場ルールにしない。
4. WBは左端から右、EBは右端から左へ進み、第10列を除外する。
5. 空き下段を選び、配置済みの下段満載がある場合のみ上段を候補にする。上段の製品自体は満載・端数のいずれでもよい。下段端数は次列へ進む。
6. 許可、予約、同一行の実行中搬送を確認して予約する。予約中の下段を上段の支持条件に使わない。荷下ろし成立後に上段を利用できる。
7. 対象領域満杯なら保留する。他系列・他用途・未割当行へ流さない。02の要求前保留と05の要求後保留を分析で分ける。

未割当行は有効な倉庫構造として保持するが、製品配置候補にしない。マップおよび倉庫詳細ダイアログでは、各行の系列／SPECIAL／未割当を同じ凡例で確認できるようにする。

理論802PLと追加入庫可能数は別である。分析では使用・予約・端数による上段不可、現在下段条件を満たす空き、将来全満載／全端数の場合の構造上の追加数を示す。未割当行・不許可・予約を除外するが、行の一時占有や実経路の到達性は各タスクで別に判定する。将来の混合比が不明なまま単一の実容量を断定しない。

## AGF初期配置

追加仕様シナリオの初期配置は、**AGF1→充電場所1、AGF2→充電場所2、AGF3→HP1、AGF4→HP2** とする。これはシミュレーション開始時の初期配置であり、通常運転時の待機先固定を意味しない。

充電場所に初期停止しているAGFは、停止位置を占有するだけであり、`charging`・`chargerId`・充電時間を発生させない。実際に充電条件を満たして充電処理へ入った時点でのみ既存の2口充電器排他を適用する。充電場所1とCHARGER1、充電場所2とCHARGER2の固定対応は推測しない。

この初期配置許可と通常待機先は分けて扱う。通常運転の復帰先は製品倉庫内の4待機場所（HP1・HP2・柱前東・柱前西）であり、充電場所1・2は初期配置時を除き通常待機先にしない。帰還先はAGFごとに固定せず、帰還開始時に `HP1 → HP2 → 柱前東 → 柱前西` の順で空きを探索する。選定した待機場所は重複選定を防ぐため帰還開始時点から予約し、到着後は占有へ移行する。優先順位は帰還先を決める時点で適用し、待機済みAGFを高優先位置へ並べ替えるためだけの移動は行わない。`PZ-HOME` / `WH-HOME` のような合成内部接続点を経路検証用に残すことはできるが、通常待機場所として扱わない。

## AGF・充電完了後

`搬送完了 → dispatch_pending → 充電判定 → 既存の目的地エリア／残量選定 → 次タスク、または製品倉庫内待機場所へ復帰`。

充電閾値以下なら通常タスクより充電を優先する。HP走行中に閾値へ達した場合はHP到着後に判定し、初期低残量の待機AGFにも充電を要求する。実行中タスクやHP走行を途中中断しない。充電途中切替・完走エネルギー見積りは未対応。

次タスクに選ばれれば現在ノードから直接荷受けへ向かい、完了したAGFだけを優遇しない。選ばれなければ、共通優先順位から選定した製品倉庫内待機場所へ `moving_to_wait` として通常の経路探索・レーン／交差点占有・シャッター待ち・電池消費・保存位置再生を適用する。パレタイズエリアでタスクを完了した場合も、その場・PZ-HOME・設備脇で通常待機してはならず、PZ EXIT→外通路→WH EAST gateを通って製品倉庫側へ戻る。待機場所到着で初めてidleへ遷移する。`taskId === null` だけでは選定しない。

製品倉庫内の4待機場所は各1台の排他資源とする。帰還先選定時は占有中・予約中の場所を除外し、優先順位上もっとも先の空き場所を選ぶ。4か所すべてが使用中または予約済みとなる矛盾状態では、充電場所・PZ・内部ホームを代替待機先にせず、理由付きで異常を記録する。待機場所への経路が一時的にシャッター・交通占有で塞がる場合は経路上の待ちとして扱い、通常待機とは区別する。

充電完了後は次タスクまたは共通優先順位で選定した製品倉庫内待機場所へ出発するときに充電器を解放し、次の充電待ち車を開始する。目標100%でも同じ。充電場所を通常待機場所として残さない。

## 集計・画面

通常空走、積載、荷受け、荷下ろし、交通待ち、荷下ろし許可待ち、HP復帰、HP待機、充電移動、充電待ち、充電、HP復帰保留を排他的に積算する。初期エリア待機はHP到着後待機と区別する。稼働率の分子は通常空走＋積載＋荷受け＋荷下ろし。表示の0.1分丸めは内訳全体に端数配分し、合計を経過時間と一致させる。

設定は基本／搬出／倉庫／AGF・充電の4区分。入力不足やエラーは区分を開いて表示する。マップは1400×850の表示用射影を使い、G01～G17と合成経路・車両へ同じ変換を適用する。文字は縦横比を補正し、実行経路はシアン。概念座標の表示変換は距離・速度・ETAを変えない。狭い画面ではマップ内部を横スクロールできる。
